Локальная система подготовки исходных данных и автоматического составления расписания колледжа. Проект строится как независимая реализация по нормативным требованиям, пользовательским сценариям и собственным приёмочным тестам: с прозрачными правилами и проверяемыми ограничениями.

Генератор расписания уже строит первый допустимый черновик: выбирает дату, последовательные интервалы и аудиторию для каждого занятия без пересечений группы, преподавателя и помещения. Оптимизация качества, версии расписаний и ручной редактор остаются следующими этапами.

## Ценность продукта

- Один источник данных для преподавателей, групп, студентов, нагрузки, специальностей, учебных планов и дисциплин.
- Предпросмотр и единый отчёт готовности к расчёту до изменения рабочих данных.
- Атомарная активация: либо сохраняется весь согласованный пакет, либо активная версия не меняется.
- Проверка дисциплин, семестров, видов занятий и часов нагрузки по учебному плану группы.
- Локальная обработка персональных данных без обязательного облачного сервиса.
- Планируемая поставка как Windows-приложение с обычным установщиком и без отдельной установки Python.

## Основные сценарии

1. Методист заполняет или выгружает единый `.xlsx`.
2. Система безопасно читает 17 основных и два необязательных канонических листа и нормализует стабильные коды.
3. Предпросмотр показывает количество объектов, фрагменты данных, блокирующие ошибки и предупреждения по часам.
4. После подтверждения все разделы сохраняются в одной транзакции SQLite.
5. Оператор может просмотреть историю и вернуть ранее активную версию без повторного импорта.
6. Перед расчётом система разворачивает нагрузку в отдельные занятия по допустимым учебным неделям и показывает блокирующую диагностику.
7. Оператор запускает расчёт и получает в локальном интерфейсе таблицу чернового расписания без конфликтов ресурсов.

## Что реализовано

- доменные модели преподавателей, групп, студентов, нагрузки, специальностей, учебных планов и дисциплин;
- канонический файл с 17 основными листами и двумя необязательными листами для цикловых комиссий и замен преподавателей;
- проверка обязательных колонок, типов, диапазонов, дублей и ссылочной целостности;
- проверка применимости плана группы и соответствия нагрузки дисциплинам и часам плана;
- отклонение формул, макросов, внешних ссылок, вложенных объектов и подозрительных ZIP-контейнеров;
- двухфазный веб-процесс `предпросмотр → активация`;
- версионированное SQLite-хранилище, идемпотентность по SHA-256 и откат к прошлой версии;
- CLI для проверки, импорта, статуса и смены активной версии;
- CP-SAT-реализация контракта `ScheduleSolver`, недельная проекция нагрузки и компактные домены допустимых дат, последовательных интервалов и аудиторий;
- учёт пяти-/шестидневной недели, праздников, переносов, сокращённых дней и недоступности преподавателя, группы и помещения;
- проверка двойного бронирования преподавателя, группы и аудитории;
- Windows functional alpha: локальный launcher, расчёт расписания и неподписанный per-user установщик без зависимости от установленного Python;
- CI на Linux и Windows с Python 3.12 и сборкой wheel.

## Быстрый запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -e .
.venv/bin/uvicorn rasp.web.app:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. Путь к базе можно изменить переменной `RASP_DATABASE_PATH`; значение по умолчанию — `data/rasp.sqlite3`.

### CLI

```bash
rasp validate path/to/import.xlsx
rasp import path/to/import.xlsx --database data/rasp.sqlite3
rasp status --database data/rasp.sqlite3
rasp readiness --database data/rasp.sqlite3
rasp solver-problem --database data/rasp.sqlite3
rasp solve --database data/rasp.sqlite3 --seed 0 --time-limit 30
rasp activate-version 1 --database data/rasp.sqlite3
```

Коды завершения: `0` — успех, `2` — ошибка Excel-валидации, `3` — ошибка хранилища, `4` — версия не найдена, `5` — нет активной версии, `6` — решатель не построил расписание. Ответы выдаются в JSON; значения ячеек и полный путь к файлу не включаются в протокол ошибок.

## Контракт Excel

Названия столбцов канонического шаблона — русские. Английские технические заголовки из предыдущих версий продолжают приниматься для обратной совместимости. Канонический формат содержит 17 основных листов и два необязательных:

- `Специальности` — код, название, квалификация, база и форма обучения;
- `Учебные планы` — специальность, год набора, редакция, период действия и статус;
- `Дисциплины` — дисциплина плана, семестр, вид занятия, контроль и плановые часы.
- `Студенты` — стабильный код, ФИО, группа, статус, период обучения, подгруппы и элективы; чувствительные персональные колонки запрещены.
- `Корпуса`, `Типы помещений`, `Оборудование`, `Аудитории` — коды, вместимость и оснащение; требования нагрузки сверяются с доступным фондом.
- `Учебные годы`, `Периоды`, `Сетка звонков` — границы года, семестры/практики/сессии/каникулы и непересекающиеся интервалы смен; нагрузка ссылается на существующий учебный год.
- `Учебные циклы` — числитель/знаменатель и произвольные циклы до 52 недель; строки нагрузки выбирают одну или несколько позиций цикла, а пустая ссылка означает занятие каждую неделю.
- `Исключения календаря`, `Недоступность` — праздники, сокращённые и перенесённые дни, а также запреты преподавателей, групп и аудиторий по датам и, при необходимости, времени. Старые 14-листовые файлы без этой пары по-прежнему поддерживаются.
- `Цикловые комиссии`, `Замены преподавателей` — необязательные справочники комиссий и временных замен; замена сверяется с преподавателем, учебным годом, датами и выбранной строкой нагрузки.

Подробные поля и правила описаны в [контракте справочных данных](docs/specs/reference-data-imports.md), а критерии допуска к генератору — в [спецификации отчёта готовности](docs/specs/schedule-readiness-report.md). Канонический синтетический пример хранится в `tests/fixtures/valid-import.xlsx`; реальные данные колледжа в репозиторий не добавляются.

## Архитектура

```mermaid
flowchart LR
    Excel["Excel .xlsx"] --> Guard["Preflight и парсер"]
    Guard --> Domain["Доменная валидация"]
    Domain --> Ready["Сверка с учебным планом"]
    Ready --> Preview["Web/API или CLI preview"]
    Preview --> Tx["Атомарная транзакция"]
    Tx --> SQLite["Версии в SQLite"]
    SQLite --> Problem["Детерминированная задача"]
    Problem --> Generator["OR-Tools CP-SAT"]
    Generator --> Draft["Черновое расписание"]
```

- `domain` не зависит от интерфейса и хранилища;
- `imports` преобразует недоверенный Excel в типизированный пакет;
- `application` координирует проверки готовности и активацию;
- `solver` задаёт независимый контракт, недельную проекцию, допустимые размещения, CP-SAT-поиск и проверку жёстких коллизий;
- `storage` хранит только полностью проверенные версии;
- `web` и `cli` являются тонкими входными адаптерами.

Целевой рабочий процесс описан в [функциональном benchmark](docs/research/timetable-functional-benchmark.md). Принципы независимой реализации зафиксированы в [ADR-002](docs/decisions/002-independent-functional-design.md).

## Безопасность и приватность

- Сервер по умолчанию работает только на loopback-адресе.
- Мутации с внешним `Origin` отклоняются; ответы защищены CSP, `X-Frame-Options`, `nosniff` и запретом кеширования.
- Реальные выгрузки колледжа должны находиться вне Git в `data/` или `imports/`.
- Для сетевой публикации потребуются отдельные аутентификация, HTTPS и настройка доверенного прокси.

## Тестирование и CI

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

Все тестовые данные синтетические. GitHub Actions запускает тесты на Linux и Windows, проверяет зависимости и компиляцию, затем собирает wheel со статическими ресурсами.
Малый детерминированный benchmark также запускается в CI и сохраняет отдельный JSON-отчёт; контракт метрик описан в [спецификации benchmark](docs/specs/solver-benchmark.md).

## Статус

Проект находится на стадии `0.4 alpha`: импорт, календарь, отчёт готовности и первый CP-SAT-поиск работают сквозным сценарием через CLI, REST API и локальный интерфейс. Решатель гарантирует отсутствие базовых конфликтов ресурсов, но пока не рассчитан на семестр среднего колледжа. Следующий срез — детерминированный benchmark и защита от чрезмерной модели. Решение по поставке описано в [ADR-001](docs/decisions/001-windows-distribution.md), семантика рабочих версий — в [ADR-003](docs/decisions/003-working-data-versions.md).
