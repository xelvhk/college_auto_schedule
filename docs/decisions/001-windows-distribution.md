# ADR-001: поставка локального приложения для Windows

- Статус: принято
- Дата: 11.08.2026

## Контекст

Основной пользователь — сотрудник учебной части, которому нужен обычный установщик без ручной установки Python. Приложение должно работать локально, сохранять SQLite-базу между обновлениями и не открывать сервис в локальную сеть.

## Решение

- поддерживаем Windows 10/11 x64;
- собираем приложение на Windows через PyInstaller в режиме `onedir`;
- добавляем небольшой launcher: он обеспечивает один экземпляр, запускает FastAPI на свободном loopback-порту и открывает локальный интерфейс в браузере;
- собираем per-user установщик Inno Setup без обязательных прав администратора;
- программные файлы и изменяемые данные разделяем: база, резервные копии и журнал находятся в `%LOCALAPPDATA%\CollegeAutoSchedule`;
- обычное удаление программы по умолчанию не удаляет пользовательскую базу; полная очистка является отдельным явным действием;
- перед миграцией схемы создаем резервную копию, а обновление проверяем сценарием `старая версия → новая версия`;
- Windows-сборка выполняется только на Windows runner: PyInstaller не является кросс-компилятором;
- перед внешним распространением подписываем EXE Authenticode-сертификатом. Подпись Inno Setup `.issig` может дополнять проверку целостности, но не убирает предупреждение Windows «неизвестный издатель».

## Почему `onedir`

Режим дает предсказуемый запуск локального сервера и статических файлов, облегчает диагностику и обновление. `onefile` откладывается до измерений: распаковка при каждом старте и более сложная диагностика не дают преимуществ для установленного приложения.

## Рассмотренные варианты

- Требовать Python у пользователя — отклонено: слишком высокий порог установки и поддержки.
- Переписать интерфейс на Electron/WinUI — отклонено для первой версии: не добавляет ценности алгоритму расписания и существенно расширяет стек.
- MSIX — отложено до необходимости управляемого корпоративного распространения.
- Публиковать неподписанный установщик как финальный релиз — отклонено; допустимо только для обозначенной внутренней альфа-версии.

## Последствия и проверки

- нужен отдельный Windows packaging workflow и smoke-тест чистой установки;
- секрет ключа подписи никогда не хранится в репозитории и доступен только защищенному release job;
- установщик проверяет архитектуру ОС, создает ярлык и запись удаления, но не включает автозапуск;
- приемка охватывает установку, первый запуск, повторный запуск, обновление, откат при неудачной миграции, удаление и сохранность базы.
