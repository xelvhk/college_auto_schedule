# Спецификация: учебные циклы

## Цель

Добавить в импортируемый набор данных формальное правило повторения занятий по
учебным неделям. Система должна поддерживать обычные еженедельные занятия,
числитель/знаменатель и произвольные циклы длиной до 52 недель, не нарушая импорт
книг предыдущих версий.

## Контракт данных

Новый необязательный лист `Учебные циклы` содержит:

| Поле | Русский заголовок | Правило |
|---|---|---|
| `cycle_code` | Код цикла | Уникальный стабильный код |
| `academic_year` | Учебный год | Ссылка на лист `Учебные годы` |
| `cycle_name` | Название цикла | Пользовательское название |
| `cycle_length_weeks` | Длина цикла в неделях | Целое число от 1 до 52 |
| `anchor_date` | Дата начала отсчёта | Дата внутри учебного года |
| `active` | Активен | По умолчанию `true` |

В лист `Нагрузка` добавляются необязательные поля:

| Поле | Русский заголовок | Правило |
|---|---|---|
| `cycle_code` | Код учебного цикла | Пусто — занятие каждую неделю |
| `cycle_week_numbers` | Номера недель цикла | Номера через `;`, например `1` или `1;3` |

Числитель и знаменатель представляются одним циклом длиной 2: позиция `1` —
числитель, позиция `2` — знаменатель. Применимость строки нагрузки к календарной
дате вычисляется относительно недели, содержащей `anchor_date`; неделя начинается
в понедельник.

## Валидация

- Код цикла уникален в пределах импортируемой версии.
- Цикл ссылается на существующий учебный год, а `anchor_date` находится внутри него.
- Если у нагрузки указан `cycle_code`, должны быть указаны номера недель цикла.
- Нагрузка и цикл относятся к одному учебному году.
- Каждый номер недели находится в диапазоне от 1 до длины выбранного цикла.
- Номера недель нормализуются, удаляются повторы и сортируются.
- Номера недель без кода цикла запрещены.
- Ошибка в любой строке блокирует атомарную активацию всего файла.

## Совместимость

- Книги без листа `Учебные циклы` принимаются как раньше.
- Строка нагрузки без новых полей действует каждую учебную неделю.
- Поле `recurrence` сохраняется для чтения старых файлов, но новые циклические
  правила задаются только структурированными полями.
- Миграция SQLite добавляет таблицу циклов и новые столбцы нагрузки без потери
  сохранённых версий.

## Команды проверки

- Узкие тесты: `.venv/bin/python -m unittest tests.test_calendar tests.test_excel_import tests.test_sqlite_storage`
- Все тесты: `.venv/bin/python -m unittest discover -s tests -v`

- Шаблон: запуск `tools/generate_import_template.mjs` через bundled Node.js и
  `@oai/artifact-tool`.

## Структура и стиль

- Доменные правила находятся в `src/rasp/domain/models.py`.
- Межстрочные и ссылочные проверки импорта находятся в `src/rasp/imports/excel.py`.
- SQLite хранит только уже полностью проверенный `ImportBatch`.
- Публичные JSON-поля используют `camelCase`, Excel-поля — русские заголовки с
  сохранением английских технических алиасов.
- Новые модели Pydantic неизменяемы и запрещают неизвестные поля.

## Стратегия тестирования

- Unit: границы длины цикла и нормализация номеров недель.
- Import integration: неизвестный цикл, несовпадающий учебный год, выход позиции
  за диапазон и совместимость старой книги.
- Storage integration: миграция схемы, атомарная запись и полное чтение циклов.
- API/CLI: новые счётчики присутствуют в предпросмотре и результате активации.
- Workbook: значения и форматы проверены инспекцией, каждый лист визуально
  отрендерен.

## Границы

- Всегда: детерминированная валидация до записи и полная транзакция активации.
- Перед отдельным решением: изменение смысла `anchor_date` или диапазона длины
  цикла.
- Никогда: эвристически интерпретировать свободный текст `recurrence` как новый
  структурированный цикл.

## Критерии готовности

- Канонический 17-листовый файл импортируется и содержит цикл длиной 2.
- Для примера нагрузки с позицией `1` система сохраняет применимость к числителю.
- Некорректные ссылки и позиции отклоняются с точными кодами ошибок.
- Старая 16-листовая книга импортируется как еженедельная.
- Полный набор тестов и сборка пакета проходят; Windows installer собирается в CI.
