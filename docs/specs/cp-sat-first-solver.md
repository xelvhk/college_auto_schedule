# Спецификация: первый CP-SAT расчёт расписания

## Цель

Дать диспетчеру колледжа первый сквозной пользовательский сценарий расчёта:
после активации корректной книги Excel программа выбирает ровно одно допустимое
размещение для каждого занятия и не допускает одновременной занятости группы,
преподавателя или аудитории. Результат показывается как непубликуемый черновик.

Этот срез подтверждает работоспособность генератора, но ещё не оптимизирует
окна, равномерность нагрузки и другие показатели качества, не сохраняет версии
расписаний и не предоставляет ручной редактор.

## Технологии

- Python 3.12 и существующие FastAPI, Pydantic, SQLite.
- Google OR-Tools CP-SAT `>=9.15,<10` (Apache-2.0).
- Локальный HTML/CSS/JavaScript без внешних ресурсов.

## Контракты

- `CpSatScheduleSolver.solve(problem, options) -> SolverResult`.
- `SolverOptions`: режим `complete`, seed и лимит времени от 1 до 300 секунд.
- `POST /api/solver/runs`: JSON `{ "mode": "complete", "seed": 0,
  "timeLimitSeconds": 30 }`; отсутствие активного импорта возвращает стабильную
  ошибку `409 no_active_import`.
- `rasp solve --database ... --seed 0 --time-limit 30` печатает тот же результат
  в JSON. Код 0 означает найденное расписание, код 6 — расчёт не дал решения.
- Каждое назначение содержит начальный интервал и полный список занятых
  интервалов, чтобы многопарные занятия корректно участвовали в проверках.

## Команды

```shell
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m rasp.cli solve --database data/rasp.sqlite3 --seed 0 --time-limit 30
.venv/bin/python -m uvicorn rasp.web.app:create_app --factory --host 127.0.0.1 --port 8765
```

## Структура

- `src/rasp/solver/cp_sat.py` — построение и запуск модели.
- `src/rasp/solver/contracts.py` — входные параметры и результат.
- `src/rasp/solver/presentation.py` — единый JSON-контракт API и CLI.
- `src/rasp/web/` — локальный REST-адаптер и интерфейс черновика.
- `tests/` — модульные, контрактные и статические UI-тесты.

## Стиль кода

Доменные модели остаются неизменяемыми Pydantic-моделями; сортировка входов и
выходов явная, сообщения пользователю — на русском, машинные коды — стабильные:

```python
model.add_exactly_one(option_vars)
model.add_at_most_one(resource_vars)
```

## Стратегия тестирования

- Модульно: допустимость, невозможная задача, многопарные конфликты,
  воспроизводимость и валидация параметров.
- Интеграционно: активный Excel-импорт → 36 назначений через CLI и REST API.
- В браузере: доступность кнопки, состояния ожидания/ошибки/успеха, таблица на
  desktop и mobile, чистая консоль и корректный сетевой запрос.
- Выпуск: полный CI и скачанный Windows EXE с проверенным SHA-256.

## Границы

- Всегда: проверять готовность задачи, ограничивать время решения, учитывать все
  занятые интервалы, возвращать детерминированно отсортированный результат.
- Согласовать отдельно: новые зависимости, изменение схемы БД и CI. Добавление
  OR-Tools для этого среза уже подтверждено пользователем.
- Никогда: не публиковать черновик автоматически, не сохранять персональные
  данные в логах, не заявлять оптимальность качества без функции цели.

## Критерии готовности

- На эталонной книге найдено 36 назначений без конфликтов ресурсов.
- Каждое назначение принадлежит домену соответствующей строки нагрузки.
- Невозможная задача имеет статус `infeasible`, а не частичный результат.
- Одинаковый вход и seed дают одинаковый упорядоченный результат.
- Запуск доступен через Python API, CLI, REST API и локальный интерфейс.
- Полный набор тестов, GitHub CI и Windows alpha-сборка успешны; EXE скачан и
  его SHA-256 зафиксирован.
