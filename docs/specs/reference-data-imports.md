# Контракт импорта справочных данных

Статус: утверждено для проектирования

Версия: 0.1 от 11.08.2026

## Назначение

Документ определяет канонические листы Excel, устойчивые идентификаторы и блокирующие проверки для учебных планов, студентов и помещений. Реальные файлы колледжа могут иметь другие названия колонок, но после сопоставления обязаны преобразовываться в этот контракт.

Импорт всегда двухфазный: сначала чтение, нормализация и полный протокол проверки без изменения базы, затем отдельное подтверждение атомарной активации версии.

## Канонические листы

### `Специальности`

| Поле | Обязательное | Правило |
|---|---:|---|
| `specialty_code` | да | Стабильный код профессии/специальности, уникальный после нормализации регистра и пробелов |
| `specialty_name` | да | Полное наименование для отображения |
| `qualification` | нет | Присваиваемая квалификация |
| `program_base` | да | `9` или `11` классов |
| `education_form` | да | Очная, очно-заочная или заочная |
| `active` | нет | По умолчанию `true` |

### `Учебные планы`

| Поле | Обязательное | Правило |
|---|---:|---|
| `curriculum_code` | да | Стабильный код редакции плана |
| `specialty_code` | да | Ссылка на специальность |
| `admission_year` | да | Год набора |
| `version` | да | Номер/обозначение утвержденной редакции |
| `valid_from`, `valid_to` | да/нет | Период применения; интервалы активных редакций не пересекаются |
| `status` | да | `draft`, `active` или `archived` |

### `Дисциплины`

Одна строка описывает объем одной дисциплины учебного плана в одном семестре и для одного вида занятия.

| Поле | Обязательное | Правило |
|---|---:|---|
| `curriculum_code` | да | Ссылка на учебный план |
| `discipline_code` | да | Индекс дисциплины/ПМ/МДК/практики внутри плана |
| `discipline_name` | да | Наименование для отображения |
| `section_code` | нет | Цикл, модуль или раздел плана |
| `semester` | да | Положительный номер семестра в пределах плана |
| `lesson_type` | да | Лекция, практика, лабораторная, консультация, аттестация или практика |
| `planned_hours` | да | Неотрицательный целый объем академических часов |
| `control_form` | нет | Экзамен, зачет, дифференцированный зачет и т. п. |

Уникальность строки: `curriculum_code + discipline_code + semester + lesson_type`. Повтор с тем же ключом является ошибкой, а не дополнительным объемом.

### `Студенты`

| Поле | Обязательное | Правило |
|---|---:|---|
| `student_code` | да | Стабильный внутренний код; единственный ключ обновления |
| `full_name` | да | ФИО для отображения; совпадение ФИО только предупреждает |
| `group_code` | да | Ссылка на существующую группу |
| `status` | да | `active`, `academic_leave`, `graduated` или `dismissed` |
| `enrollment_date` | нет | Дата начала обучения/членства в группе |
| `end_date` | нет | Дата окончания; не раньше даты зачисления |
| `subgroup_codes` | нет | Список номеров подгрупп этой группы |
| `elective_codes` | нет | Список стабильных кодов выбранных элективов |

В каноническом файле номера подгрупп перечисляются через `;`, например `1;2`; коды элективов используют тот же разделитель. Номер подгруппы должен находиться в диапазоне от `1` до `subgroup_count` соответствующей группы.

Файл не должен содержать телефоны, адреса, даты рождения, паспортные данные, сведения о здоровье, оплате, оценках или посещаемости. Такие колонки отклоняются либо явно исключаются до загрузки.

### `Корпуса`, `Типы помещений`, `Оборудование`, `Аудитории`

- `Корпуса`: `building_code`, `building_name`, необязательный `active`.
- `Типы помещений`: `room_type_code`, `room_type_name`, необязательный `active`.
- `Оборудование`: `equipment_code`, `equipment_name`, необязательный `active`.
- `Аудитории`: `room_code`, `room_name`, `building_code`, `room_type_code`, положительная `capacity`, необязательные `equipment_codes` через `;` и `active`.

Каждая аудитория ссылается на существующий корпус, тип и оборудование. Поля нагрузки `room_type`, `room_capacity` и `required_equipment_codes` задают минимальные требования. Отсутствие подходящей аудитории не отменяет импорт справочников, но создаёт явный дефицит и блокирует будущий расчёт до исправления.

## Нормализация

- коды обрезаются по краям, приводятся к согласованному регистру и проверяются до поиска дублей;
- пустая строка и отсутствующее необязательное значение считаются `null`, но число `0` не считается пустым;
- даты преобразуются только из однозначного Excel-значения или формата ISO `YYYY-MM-DD`;
- формулы, макросы, внешние ссылки и вычисленные ключи запрещены;
- ФИО и наименования нормализуются только для поиска предупреждений и никогда не заменяют стабильный код.

## Матрица проверок

| Категория | Блокирующие ошибки | Предупреждения |
|---|---|---|
| Формат | неверный тип/диапазон, неизвестное обязательное значение, запрещенная формула | неизвестная необязательная колонка |
| Дубли | повтор стабильного или составного ключа в файле; два разных объекта обновляют один активный код | одинаковые ФИО/названия при разных кодах |
| Ссылки | план без специальности; дисциплина без плана; студент без группы; подгруппа не принадлежит группе | ссылка на неактивную, но исторически существующую запись |
| Версии | пересекающиеся активные периоды редакций; две активные редакции для одной области применения | новая редакция меняет название существующего кода |
| Часы | отрицательные часы; нагрузка с отсутствующей дисциплиной; сумма нагрузки превышает объем плана | распределено меньше часов плана до завершения подготовки |
| Контингент | студент активен в несовместимых группах на одну дату; дата окончания раньше начала | одинаковое ФИО в одной группе; отсутствует необязательная дата |
| Идемпотентность | один файл дает разные нормализованные данные при повторной проверке | файл с новым SHA-256 не меняет данные |

Любая блокирующая ошибка отменяет весь пакет. Предупреждения показываются до активации и требуют явного подтверждения, если профиль колледжа не помечает их информационными.

## Межфайловая целостность перед расчетом

1. У каждой группы есть ровно один применимый активный учебный план.
2. Каждая строка нагрузки ссылается на дисциплину этого плана, группу/подгруппу и активного преподавателя.
3. Суммы часов сравниваются по ключу `план + дисциплина + семестр + вид занятия`; превышение блокирует расчет.
4. Общий объем нагрузки раскладывается на целое число событий либо остаток оформлен отдельным подтвержденным правилом.
5. Каждая часть нагрузки размещается не более одного раза; у группы, подгруппы, преподавателя, аудитории и участвующего студента нет временных пересечений.
6. Вместимость аудитории покрывает фактический состав группы/подгруппы на дату занятия.

## Приемка

- для каждого листа есть валидный синтетический шаблон и набор негативных файлов;
- повторная загрузка одного файла не создает версии-дубликаты или записи-дубликаты;
- каждая ошибка содержит лист, строку, колонку, код правила и понятный способ исправления без записи исходного значения в лог;
- сбой на любой стадии активации оставляет предыдущую версию целиком активной;
- режим полной синхронизации студентов показывает список деактивируемых записей и требует отдельного подтверждения.
