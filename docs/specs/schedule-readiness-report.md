# Спецификация отчёта готовности к расчёту

Статус: реализовано

Версия: 0.1 от 13.08.2026

## Цель

Перед запуском будущего `ScheduleSolver` оператор должен получить единый
детерминированный ответ: можно ли строить расписание на активной версии данных,
какие ошибки это блокируют и какие предупреждения требуют внимания.

Отчёт не изменяет данные и не заменяет Excel-валидацию. Корректный пакет можно
активировать даже при неготовности к расчёту, чтобы исправлять исходные данные
последовательно.

## Контракт

Отчёт содержит:

- `isReady` — `true`, только если нет блокирующих ошибок;
- `errorCount` и `warningCount`;
- упорядоченный список `issues` со стабильными `code`, `severity`, `message`,
  разделом источника, кодом объекта и рекомендацией по исправлению.

В отчёт не включаются ФИО, исходные значения ячеек, абсолютные пути или другие
персональные данные.

## Правила первой версии

Блокируют расчёт:

- отсутствуют преподаватели, группы, нагрузка, учебные планы или дисциплины;
- отсутствуют учебные годы, периоды обучения или сетка звонков;
- нагрузка не соответствует выбранному учебному плану;
- для строки нагрузки нет подходящей активной аудитории по типу, вместимости и
  оборудованию.

Предупреждают, но не блокируют:

- часы учебного плана распределены не полностью;
- в календаре нет ни одного исключения;
- не задана недоступность ни одного ресурса.

Последние два предупреждения означают необходимость подтверждения локальных
условий колледжа, а не обязательное наличие запретов.

## Интерфейсы

- Python: `analyze_schedule_readiness(batch) -> ReadinessReport`;
- CLI: `rasp readiness --database data/rasp.sqlite3`;
- API: `GET /api/readiness` для активной версии;
- предпросмотр Excel возвращает тот же объект `readiness` до активации.

Если активной версии нет, CLI завершает работу кодом `5`, API отвечает `409` со
стабильным кодом `no_active_import`.

## Границы

- Всегда: детерминированный порядок, стабильные коды, отсутствие персональных
  данных, тест на каждое правило.
- Отдельное решение: нормативные ссылки и настраиваемые профили правил.
- Не входит: поиск расписания, конфликты уже размещённых занятий,
  числитель/знаменатель и произвольные циклы.

## Критерии готовности

1. Канонический синтетический файл получает `isReady=true` без ошибок.
2. Дефицит аудитории и отсутствие обязательного раздела дают объяснимую ошибку.
3. Недораспределённые часы дают предупреждение и не меняют `isReady`.
4. CLI, API и Excel-предпросмотр возвращают один и тот же логический отчёт.
5. Повторный анализ одного пакета возвращает одинаковый порядок проблем.
