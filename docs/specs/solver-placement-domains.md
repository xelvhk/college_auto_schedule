# Спецификация допустимых размещений занятий

Статус: реализовано

Версия: 0.1 от 17.08.2026

## Цель

Дополнить подготовленную задачу решателя компактным и детерминированным набором
допустимых размещений для каждой строки нагрузки. Размещение задаёт фактическую
дату, последовательность интервалов сетки звонков и подходящую аудиторию.

Результат служит входным доменом переменных будущей реализации CP-SAT и позволяет
до запуска поиска объяснить, почему для строки нагрузки не осталось вариантов.

## Допущения и календарная семантика

1. `study_week_type=five_days` разрешает понедельник–пятницу,
   `study_week_type=six_days` — понедельник–субботу. Пустое или неизвестное
   значение блокирует подготовку задачи.
2. `holiday` исключает дату, `working_day` явно делает дату рабочей,
   `shortened_day` оставляет только интервалы, заканчивающиеся не позже заданного
   времени.
3. `transferred_day` заменяет исходную дату на `transferred_to`. Семестр, день
   учебной недели и позиция цикла определяются по исходной дате; недоступность и
   сокращение проверяются по фактической дате.
4. Один интервал сетки звонков содержит целое число 45-минутных академических
   часов. Более длинное занятие занимает последовательные номера занятий одной
   смены; разрыв нумерации или смены разрывает последовательность.
5. Аудитория должна быть активной и одновременно удовлетворять типу, вместимости
   и оснащению строки нагрузки.
6. Интервал недоступности трактуется как полуоткрытый диапазон `[начало, конец)`;
   касание границ не является пересечением. Недоступность без времени исключает
   ресурс на весь фактический день.
7. Чтобы не размножать одинаковые варианты для каждого занятия, варианты
   хранятся один раз в `WorkloadPlacementDomain` и используются всеми
   `LessonDemand` соответствующей строки нагрузки.

## Контракт

- `PlacementOption`: фактическая дата, упорядоченные `slot_codes` и код аудитории.
- `WorkloadPlacementDomain`: код строки нагрузки и уникальные упорядоченные
  варианты.
- `SolverProblem.placement_domains`: один домен на каждую строку нагрузки.
- Если домен пуст, диагностика содержит ошибку `no_eligible_placements`.
- Если тип учебной недели неизвестен, диагностика содержит
  `unsupported_study_week_type`.
- Сетка звонков с длительностью, не кратной 45 минутам, блокируется кодом
  `unsupported_bell_slot_duration`.
- Подготовка блокируется до чрезмерного потребления памяти, если суммарно
  получается более 1 000 000 вариантов.

Публичные JSON-поля добавляются к существующему ответу без удаления или изменения
текущих полей: `placementDomainCount`, `placementOptionCount` и
`placementDomainSamples`.

## Структура и команды

- модели: `src/rasp/solver/contracts.py`;
- календарная проекция: `src/rasp/solver/placements.py`;
- сборка задачи: `src/rasp/solver/preparation.py`;
- JSON-представление: `src/rasp/solver/presentation.py`;
- тесты: `tests/test_solver_placements.py`, интеграционные CLI/API-тесты.

```bash
PYTHONPATH=src .venv/bin/python -m unittest tests.test_solver_placements -v
PYTHONPATH=src .venv/bin/python -m unittest tests.test_cli tests.test_web_api -v
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m compileall -q src tests
.venv/bin/python -m pip wheel . --no-deps --no-build-isolation --wheel-dir /tmp/rasp-wheel
```

## Границы

- Всегда: детерминированная сортировка, стабильные коды ошибок, отсутствие ФИО в
  диагностике, ограничение объёма материализации.
- Не менять: Excel-контракт, схему SQLite и существующие поля CLI/API.
- Не входит: переменные CP-SAT, поиск решения, фиксация занятий, потоки и
  синхронные связки.
- Новые зависимости не добавляются.

## Критерии готовности

1. Канонический пакет создаёт варианты только для шестидневной недели, без
   праздника и трёх дней недоступности преподавателя.
2. Пятидневная группа не получает субботних вариантов.
3. Перенос с рабочего дня на выходной создаёт вариант на новой дате и удаляет
   исходную.
4. Сокращённый день и частичная недоступность исключают пересекающиеся интервалы.
5. Неподходящие и недоступные аудитории отсутствуют в вариантах.
6. Для занятий длительностью четыре академических часа используются два
   последовательных двухчасовых интервала.
7. Python, CLI, API и Excel-предпросмотр дают одинаковые количества вариантов.
8. Полный набор тестов, wheel, GitHub CI и Windows installer проходят.
