# Спецификация каркаса задачи составления расписания

Статус: реализовано

Версия: 0.1 от 17.08.2026

## Цель

Подготовить стабильную границу между импортированными данными и будущим
оптимизационным движком. Один и тот же активный пакет должен детерминированно
превращаться в набор требований к занятиям, пригодный для передачи реализации
`ScheduleSolver`.

Срез не назначает занятия на даты, интервалы и аудитории. Он показывает объём
будущей задачи, допустимые календарные недели и блокирующие проблемы до запуска
поиска.

## Принятые допущения

1. Одна строка нагрузки порождает
   `total_academic_hours / event_duration_hours` отдельных требований.
2. Допустимая неделя начинается в понедельник и пересекается хотя бы с одним
   периодом обучения нужного учебного года и семестра.
3. Для циклической нагрузки номер недели вычисляется существующим календарным
   правилом относительно якорной даты цикла.
4. Недельный уровень не выбирает учебный день и не предполагает пяти- или
   шестидневную неделю. Точные даты, интервалы и аудитории добавляются отдельным
   [доменом допустимых размещений](solver-placement-domains.md).
5. Готовность входных данных проверяется существующим отчётом; дополнительные
   ошибки проекции имеют отдельные стабильные коды.
6. За один запуск материализуется не более 100 000 требований; превышение
   блокируется до выделения большого объёма памяти и требует разделить расчёт.

## Контракт

- `SolverProblem` содержит упорядоченные `LessonDemand` и диагностические
  сообщения.
- `LessonDemand` содержит стабильный код, ссылку на строку нагрузки, ресурсы,
  длительность и упорядоченные допустимые начала недель.
- `ScheduleSolver` принимает `SolverProblem` и `SolverOptions`, возвращает
  `SolverResult`; конкретный оптимизатор остаётся заменяемым.
- `ScheduleAssignment` представляет одно размещённое занятие.
- Проверка размещений возвращает стабильные ошибки при повторном использовании
  преподавателя, группы или аудитории в одной дате и интервале.

Публичные JSON-поля используют `camelCase`; перечисления — `snake_case`, как в
существующих API проекта. Диагностика не содержит ФИО и исходных значений ячеек.

## Интерфейсы

- Python: `build_solver_problem(batch) -> SolverProblem`;
- Python: `find_assignment_conflicts(assignments) -> tuple[SolverDiagnostic, ...]`;
- CLI: `rasp solver-problem --database data/rasp.sqlite3`;
- API: `GET /api/solver/problem` для активной версии;
- предпросмотр Excel содержит объект `solverProblem` до активации.

Если активной версии нет, CLI завершает работу кодом `5`, API отвечает `409` с
кодом `no_active_import`.

## Границы

- Всегда: стабильная сортировка, воспроизводимые идентификаторы, отсутствие
  персональных данных, тест на каждую коллизию ресурса.
- Отдельное решение: точная сетка допустимых дат, последовательные интервалы,
  фиксированные занятия, потоки и подгруппы.
- Не входит: OR-Tools, поиск решения, целевая функция, сохранение расписания и
  пользовательский редактор.
- Не добавлять новую внешнюю зависимость для этого среза.

## Критерии готовности

1. Канонический файл создаёт ожидаемое число требований с одинаковым порядком
   при повторном запуске.
2. Цикл нагрузки ограничивает допустимые недели.
3. Отсутствие допустимых учебных недель даёт блокирующую диагностику.
4. Повтор преподавателя, группы и аудитории в одном слоте выявляется раздельно;
   разные даты или интервалы не конфликтуют.
5. Python, CLI, API и Excel-предпросмотр возвращают один логический результат.
6. Полный набор тестов, сборка wheel, GitHub CI и Windows installer проходят.
