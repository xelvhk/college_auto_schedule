# Функциональный benchmark системы расписания колледжа

Статус: принято как продуктовый ориентир

Дата анализа: 12.08.2026

## Цель анализа

Цель проекта — реализовать зрелый рабочий процесс составителя расписания на синтетических и разрешённых обезличенных данных, сохранив современную архитектуру, объяснимость и проверяемость.

Требования формируются из нормативных документов, интервью и пользовательских операций, а затем фиксируются собственными спецификациями и приёмочными тестами. Чужой исходный или декомпилированный код, закрытые алгоритмы и проприетарные форматы не используются.

## Наблюдаемая функциональная архитектура

1. Справочники групп, преподавателей, дисциплин, аудиторий, кафедр и корпусов.
2. Учебные планы с общей и понедельной нагрузкой, подгруппами, потоками и преподавателями.
3. Пожелания и запреты преподавателей, требования занятий к аудиториям, календарь и звонки.
4. Предварительный анализ исходных данных отдельно по группам, преподавателям и аудиториям.
5. Автоматическое построение: быстрый/аналитический и короткий/полный режимы.
6. Несколько последовательных циклов улучшения и отдельная оптимизация аудиторий.
7. Редактор по группам, преподавателям и аудиториям, закрепленные занятия и неразмещенная нагрузка.
8. Числовая оценка качества варианта и экспорт для печати/сайта.

## Матрица функционального покрытия

| Возможность | Реализация проекта | Приемка |
|---|---|---|
| Справочники и учебные планы | Типизированные сущности, SQLite, версионированный Excel-импорт | Ссылки однозначны, повторный импорт не создает дублей |
| Понедельная/семестровая нагрузка | Нормализованные строки нагрузки и календарные шаблоны | Суммы плана, назначений и размещений сверяются |
| Пожелания преподавателей | Жесткая доступность и взвешенные предпочтения | Запрет никогда не нарушается, предпочтение влияет на score |
| Требования аудиторий | Тип, вместимость, оборудование, корпус, желаемые/жесткие аудитории | Для каждого занятия известен допустимый набор помещений |
| Анализ исходных данных | `ReadinessAnalyzer` с группировкой проблем по объектам | Расчет нельзя запустить при блокирующей проблеме |
| Черновой расчет | Стадия размещения наиболее ограниченных занятий | При совместимых данных получается допустимый черновик |
| Полный расчет | `ScheduleSolver` достраивает остаток с лимитом времени | Размещено 100% нагрузки либо выдан объяснимый остаток |
| Оценка качества | Версионированная функция score с видимыми весами | Один вариант воспроизводимо сравнивается с другим |
| Повторная оптимизация | Детерминированные циклы улучшения с seed и остановкой | Score не ухудшается без явного разрешения |
| Оптимизация аудиторий | Отдельная стадия назначения/переназначения помещений | Временная сетка не меняется, жесткие требования сохранены |
| Ручной редактор | Сетки группы/преподавателя/аудитории и блокировки | Любой перенос проходит ту же проверку жестких правил |
| Неразмещенная нагрузка | Отдельная очередь с причиной для каждой строки | Нельзя опубликовать неполный вариант без явного исключения |
| Недельные варианты | Единая реляционная модель событий с календарным шаблоном | Поддерживаются разные недели без набора файлов `.rN` |
| Экспорт | Excel, PDF, HTML/read-only API | Выход содержит версию данных, правил и расписания |

## Конвейер расчета

```text
Импорт и нормализация
        ↓
Анализ готовности и дефицитов
        ↓
Фиксированные занятия и блокировки
        ↓
Черновое размещение наиболее трудных занятий
        ↓
Достроение оставшейся нагрузки
        ↓
Оптимизация качества
        ↓
Оптимизация аудиторий
        ↓
Ручная доводка и частичный перерасчет
        ↓
Контроль часов и публикация
```

## Функция качества первой версии

Итоговая оценка минимизируется и включает отдельные измеримые компоненты:

- окна и крайние свободные слоты групп;
- нормативные и сверхнормативные окна преподавателей;
- число смен и рабочих дней преподавателя;
- перегрузку/недогрузку по дисциплине в день;
- разрывы связанных и сдвоенных занятий;
- равномерность нагрузки по неделе;
- переходы между корпусами;
- нарушение мягких предпочтений;
- отклонение от опубликованного или закрепленного варианта;
- сходство расписаний выбранных недель, если оно включено пользователем.

Каждый компонент сохраняется отдельно. Общая сумма без расшифровки не считается достаточным объяснением качества.

## Критерий готовности рабочего процесса

Готовность к опытной эксплуатации заявляется только после проверки на согласованном обезличенном наборе:

- система размещает весь обязательный объём нагрузки;
- в результате нет жёстких конфликтов;
- диспетчер может выполнить эквивалентные операции анализа, блокировки, перерасчета, оптимизации и экспорта;
- отчёт показывает остаток, нарушения и компоненты качества;
- время построения и качество согласованы с учебной частью на нескольких реальных по структуре сценариях.

Внутренние алгоритмы и интерфейс оцениваются по сопровождаемости, прозрачности и результатам приёмочных сценариев.
